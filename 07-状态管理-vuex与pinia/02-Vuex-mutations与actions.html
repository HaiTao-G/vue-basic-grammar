Vuex：mutations 与 actions

上一个文件只讲了"读"。这一页讲"改"。
Vuex 有个硬性规定：改 state 必须 commit 一个 mutation，不能直接 this.$store.state.count++；异步操作（发请求、定时器）则放到 actions 里， 由它去 commit mutation。

一、mutations：同步修改 state

当前 count = {{ $store.state.count }}

组件里：this.$store.commit('ADD', 1)
store 里：mutations: { ADD(state, n) { state.count += n } }
→ commit 的作用：明确"是谁、用什么方式改了数据"，devtools 里能看到每一次变化的快照

二、actions：处理异步，内部再 commit

⏳ 请求中，请稍候...
组件里：this.$store.dispatch('addAsync', 5)
store 里：
actions: {
  addAsync({ commit }, n) {
    commit('SET_LOADING', true)
    setTimeout(() => { // 真实项目这里是发请求
      commit('ADD', n)
      commit('SET_LOADING', false)
    }, 1000)
  }
}

规律：action 自己不碰 state，它只负责"什么时候改"，真正改数据还是交给 mutation。

三、错误示范：直接改 state 会怎样

本页的 store 开启了 strict: true（严格模式），任何不经过 mutation 的修改都会被拦截。

❌ 直接改：this.$store.state.count++
   → 严格模式下抛错：do not mutate vuex store state outside mutations
✅ 正确：this.$store.commit('ADD', 1)

四、mutation 与 action 对比

对比项 mutations actions
职责 真正修改 state 处理业务逻辑 / 异步，再 commit
能否异步 必须同步 可以异步
组件里调用 this.$store.commit('名字', 参数) this.$store.dispatch('名字', 参数)
第一个参数 state context（含 commit / dispatch / state）
devtools 追踪 每次变化都有记录 记录的是它内部 commit 的那次

为什么 mutation 必须同步？因为 devtools 需要知道"这次变化到底是哪个操作引起的"。 如果 mutation 里塞了定时器/请求，等回调执行时早就过了那个时间点，工具就记录不准了。 所以：同步的改动用 commit，异步的先 dispatch 再 commit。
