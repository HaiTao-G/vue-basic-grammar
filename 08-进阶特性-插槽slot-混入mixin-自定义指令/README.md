## 三、核心概念速查表

### 1. 插槽三大类型速查

```html
<!-- 1. 默认插槽 -->
<my-box>
  <p>这是填充进默认 slot 的内容</p>
</my-box>

<!-- 2. 具名插槽（推荐使用 # 简写） -->
<my-card>
  <template #header><h3>标题</h3></template>
  <template #default><p>主体内容</p></template>
  <template #footer><button>确认</button></template>
</my-card>

<!-- 3. 作用域插槽（解构获取子组件抛出的数据） -->
<my-table :data-list="list">
  <template #action="{ row, index }">
    <button @click="del(index)">删除 {{ row.name }}</button>
  </template>
</my-table>
```

### 2. 自定义指令 5 个生命周期钩子

| 钩子函数 | 调用时机 | 典型用途与注意事项 |
| :--- | :--- | :--- |
| **`bind`** | 只调用一次，指令第一次绑定到元素时 | 初始化样式、添加标记。**注意此时元素未插入父 DOM，`el.focus()` 无效** |
| **`inserted`** | 被绑定元素插入父节点时调用 | **真实 DOM 操作必选**（如自动聚焦、获取 DOM 宽高尺寸） |
| **`update`** | 所在组件的 VNode 更新时调用 | 依赖的数据变化时触发，但子 VNode 可能尚未更新 |
| **`componentUpdated`** | 指令所在组件的 VNode **及其子 VNode** 全部更新后调用 | 必须等子组件 DOM 重新排版完毕后计算的操作 |
| **`unbind`** | 只调用一次，指令与元素解绑时调用 | **清理垃圾**：移除 `window` / `document` 原生监听器、清理定时器，避免内存泄漏 |

### 3. Mixin 选项合并规则（面试核心考点）

1. **`data` 数据对象**：进行递归合并，键名冲突时**以组件自身数据优先**。
2. **生命周期钩子**：同名钩子合并为一个数组，**全部都会执行**；**Mixin 钩子先于组件自身钩子执行**。
3. **值为对象的选项（`methods` / `computed` / `components`）**：合并为同一个对象；键名冲突时**以组件自身的键值对优先**。

## 四、经典高频面试题与避坑指南

### Q1：编译作用域的规则是什么？
> **答：** “父级模板里的所有内容都是在父级作用域中编译的；子级模板里的所有内容都是在子级作用域中编译的”。  
> 父组件给插槽传的内容只能直接访问父组件的变量；如果要访问子组件的数据，必须通过**作用域插槽**。

### Q2：`v-slot` 能直接写在普通 HTML 标签（如 `<div>`）上吗？
> **答：不能！**  
> `v-slot` 只能添加在 `<template>` 上（唯一的特例是：当组件**只有默认插槽**时，可以直接写在子组件标签本身上，如 `<my-comp v-slot="data">`）。

### Q3：为什么 Vue 3 推崇 Composition API，而建议弃用 Mixin？
> **答：** Mixin 存在三个不可忽视的架构缺陷：
> 1. **来源不清晰**：一个组件混入多个 mixin 后，模板中引用的变量不知道出自哪一个。
> 2. **命名冲突**：不同 mixin 或组件自身存在同名属性/方法时会发生覆盖。
> 3. **隐式依赖，难以灵活传参**：Mixin 之间无法像函数一样清晰地声明入参和返回值。而 Vue 3 的组合式函数（Composables）完美解决了这三点。
