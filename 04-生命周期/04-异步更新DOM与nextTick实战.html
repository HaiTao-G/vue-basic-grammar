04 - 异步 DOM 更新机制与 $nextTick 原理实战

💡 核心痛点：为什么修改了数据，不能立即拿到最新的 DOM？
Vue 采用的是异步队列更新机制（Asynchronous Update Queue）。当你修改数据时，Vue 不会马上重绘 DOM，而是开启一个队列缓冲同一个事件循环中的所有数据变更，并在下一个 tick（利用 Promise 等微任务）统一刷新视图。
$nextTick 的作用：在下次 DOM 更新循环结束之后执行延迟回调。在修改数据之后立即使用它，然后等待 DOM 更新。

📖 $nextTick 的两种语法与底层原理

语法方式 代码示例 特点说明
回调函数形式 
this.msg = '新数据';
this.$nextTick(() => {
  // 此时 DOM 已更新
  console.log(this.$refs.box.innerText);
});
 最经典写法，兼容性好。
async / await 形式 (推荐) 
async update() {
  this.msg = '新数据';
  await this.$nextTick();
  // 此时已等待 DOM 更新完毕
  console.log(this.$refs.box.innerText);
}
 代码没有深层嵌套回调，可读性极佳。
🧠 深入底层：$nextTick 是如何实现的？
Vue 内部做异步降级兼容处理，优先使用微任务（MicroTask）： Promise.then ➜ MutationObserver ➜ setImmediate ➜ setTimeout(fn, 0)。
微任务在当前宏任务末尾立即执行，避免了无谓的页面重绘和性能损耗。
