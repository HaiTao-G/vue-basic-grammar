Vuex 与 Pinia：对比与选型

同一个功能（一个计数器 + 异步加一），左右两边分别用 Vuex 和 Pinia 实现，都真实运行着。
点一点两边的按钮，感受一下"改数据"的写法差异，再看下面的代码对照。

同一个功能，两套实现

Vuex 3 实现

读：$store.state.count

{{ $store.state.count }}

改数据必须走 commit → 触发 mutation → 修改 state，三层链路。

Pinia 2 实现

读：counter.count

{{ counter.count }}

改数据直接调 action，action 里 this.count++ 就完事了，没有中间层。

代码对照

Vuex 版

// 定义
const store = new Vuex.Store({
  state: { count: 0 },
  mutations: {              // 必须有
    INC(state) { state.count++ }
  },
  actions: {
    incAsync({ commit }) {
      setTimeout(() => commit('INC'), 500)
      // action 自己不碰 state，还得转手 commit
    }
  }
})

// 组件里
new Vue({ el: '#app', store })

// 读
this.$store.state.count

// 改（同步）
this.$store.commit('INC')

// 改（异步）
this.$store.dispatch('incAsync')

Pinia 版

// 定义
const useCounter = Pinia.defineStore('counter', {
  state: () => ({ count: 0 }),
  actions: {                 // 只有这个
    inc() { this.count++ },
    async incAsync() {
      await new Promise(r => setTimeout(r, 500))
      this.count++
      // 同步异步都直接改，不用绕
    }
  }
})

// 组件里
Vue.use(Pinia.PiniaVuePlugin)
new Vue({ el: '#app', pinia: Pinia.createPinia() })

// 读
const counter = useCounter()
counter.count

// 改（同步 / 异步都一样）
counter.inc()
counter.incAsync()

逐项对比

对比项 Vuex 3 Pinia 2
核心概念 state / getters / mutations / actions（四件套） state / getters / actions（三件套）
改 state 必须 commit mutation 直接改（action 里 this.xxx）
异步 actions 里 commit actions 里直接改，async/await 直接用
拆模块 modules + namespaced + 前缀字符串 'cart/ADD' 直接建多个 store，互相 import 就行
在组件里用 this.$store + map 系列辅助函数 useXxxStore() 一行搞定
TypeScript 支持一般，类型推断弱 原生友好，类型推断强
体积 较大 更小（约 1.5KB）
devtools 调试 支持（时间旅行） 支持
官方定位 Vue 2 时代的标准方案，现处于维护状态 Vue 3 官方推荐，也是 Vue 2.7 可用的新方案

那到底用哪个？

1. 新项目（尤其 Vue 3）→ 直接上 Pinia。官方推荐，心智负担小，TS 友好。

2. 已有的 Vue 2 + Vuex 项目 → 保持 Vuex，别为了新而迁移。 Vuex 3 依旧能用，迁移收益不大、风险不小。

3. 在学习阶段的 Vue 2.7 项目里 → 建议两个都练。 Vuex 能帮你理解"为什么要约束改数据的方式"，Pinia 代表现在的写法。 面试里这两个都常被问到。

4. 判断标准其实很简单：团队熟什么、项目是什么版本，就用什么。 技术选型里"团队能维护"永远比"技术新"重要。

补充：本项目是 Vue 2.7.16，Pinia 2.1.7 能正常跑（靠 vue-demi 桥接）。 真正的 Vue 2.6 及更低版本用 Pinia 需要额外引入 @vue/composition-api，会麻烦一些。
