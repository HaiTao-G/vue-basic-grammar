计算属性 computed

是什么：计算属性是基于响应式数据派生出来的值，写在 computed 里。 它像一个"聪明的变量"——依赖的数据变了，它会自动重新算；依赖没变，它就直接返回缓存的旧值，不重复计算。
适用场景：需要由两个或多个 data 计算得来的值（全名、总价、过滤列表等）。

一、基础用法：拼接全名

姓： 名：
完整姓名（computed）：{{ fullName }}

试着只改"姓"或"名"，fullName 会自动更新；不用你手动去同步两个字段。

二、缓存特性：computed vs methods（重点理解）

商品单价： 购买数量： 无关数据：
总价（computed）：¥{{ total }} ｜ computed 重算次数：{{ computedCount }}
总价（methods 调用）：¥{{ getTotal() }} ｜ methods 调用次数：{{ methodCount }}

解释：页面里 {{ total }} 和 {{ getTotal() }} 都会渲染， 但 computed 有缓存——只有 price/count 变化才会重算（computedCount 才 +1）； 而 methods 每次渲染都执行（methodCount 一直涨）。
自己验证：只改"无关数据"，会发现 methodCount 又涨了，但 computedCount 纹丝不动。

三、可写的计算属性（getter / setter）

默认 computed 是只读的（只有 get）。给它加上 set，就能"反过来"： 直接改 fullName，会自动把姓和名拆开写回。

fullName（可编辑）：
拆开后 —— 姓：{{ firstName2 }} ｜ 名：{{ lastName2 }}

四、computed 与 methods 怎么选

对比项 computed（计算属性） methods（方法）
写法 模板里 {{ fullName }}（不加括号） 模板里 {{ getTotal() }}（加括号）
是否有缓存 有，依赖不变不重算 无，每次都执行
适合 依赖 data 算出来的"值" 事件处理、不依赖缓存的逻辑
能否异步 不能（必须是同步 return） 可以

一句话：要的是一个"值"就优先用 computed；要的是"做一件事"（尤其是带副作用/异步）就用 methods 或 watch。
